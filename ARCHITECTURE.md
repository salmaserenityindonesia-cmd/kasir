## Overview
Open Source Point of Sale (OSPOS) built on the CodeIgniter 4 PHP framework. It provides point-of-sale features, inventory management, customer tracking, and reporting. The application follows a classic Model-View-Controller (MVC) pattern.

## Components

### Controllers
- **Purpose:** Handle incoming HTTP requests, process logic, and return views or JSON responses.
- **Location:** `app/Controllers/`
- **Dependencies:** `app/Models/`, `app/Libraries/`, `app/Helpers/`
- **Dependents:** `public/index.php` via Routing

### Models
- **Purpose:** Encapsulate database interactions and business data logic.
- **Location:** `app/Models/`
- **Dependencies:** `app/Database/`, CodeIgniter Query Builder
- **Dependents:** `app/Controllers/`

### Views
- **Purpose:** Provide HTML templates for the user interface.
- **Location:** `app/Views/`
- **Dependencies:** Helper functions for formatting (e.g., `app/Helpers/tabular_helper.php`)
- **Dependents:** `app/Controllers/`

### Database Migrations
- **Purpose:** Manage schema changes and initial data seeding.
- **Location:** `app/Database/Migrations/`
- **Dependencies:** CodeIgniter Migration runner
- **Dependents:** Deployment/Setup processes

## Data Flow
1. User interacts with the UI in the browser, triggering an HTTP request.
2. The request is routed through `public/index.php` to the appropriate Controller in `app/Controllers/`.
3. The Controller may invoke one or more Models in `app/Models/` to fetch or update data in the MySQL database.
4. The Controller passes the retrieved data to a View in `app/Views/` to render the HTML, or returns a JSON response for AJAX requests.
5. The rendered content is sent back to the client.

## Conventions

- **Testing:** PHPUnit tests located in the `tests/` directory.
